# 工程亮点

## 认证与安全

- 用户 App API 和商户后台使用两套认证边界。
- Bearer Token 支持 Redis 存储和本地降级缓存。
- Redis 活跃标记实现同账号单 Token。
- 拦截器统一处理未认证请求，避免每个 Controller 重复判断。

## 金额与库存一致性

- 金额统一使用 `BigDecimal`。
- 销售、取消和库存回补在事务中执行。
- FIFO 批次分配结果被持久化，取消订单时可精确逆向回补。
- 客户赊账额度与财务结算同步更新。

## 数据库与接口

- 使用 MyBatis-Plus 完成分页、条件查询和逻辑删除。
- 关键唯一性约束由数据库和服务层双重校验。
- 雪花 ID 序列化为字符串，解决 JavaScript 大整数精度问题。
- 管理端与用户端 API 分离，减少前端暴露后台字段。

## 图片性能

- 图片卡片的原图平均体积远高于实际显示需要。
- 后端自动生成 `480×480` JPEG 缩略图，原图保留。
- 12 张菜品图由约 `5.79 MiB` 降至 `0.39 MiB`，减少约 `93.3%`。
- Nginx 开启静态直出和 30 天缓存。

## 签收与报损闭环

- 客户主动签收写入 `MANUAL`，系统超时签收写入 `AUTO`。
- 已配送满 12 小时的订单由定时任务自动签收。
- 自动签收订单永久拒绝报损，迟到的签到请求也不能改成主动签收。
- 主动签收订单按商户配置的 1 至 72 小时窗口报损，默认 14 小时。
- 订单接口下发当前 `claimWindowHours`，确认签收弹窗在提交前显示准确时限。
- 报损支持图片和短视频证据，经过商户审核后可以生成 0 元补发单。

## 订单状态同步

- 小程序和 Android 进入订单页立即拉取状态。
- 页面可见时每 8 秒静默轮询，隐藏或卸载时清理定时器。
- 请求层支持静默失败，短暂断网不会周期性弹出 Toast。
- 使用订单状态指纹避免无变化时重复渲染。
- 同时只允许一个请求，防止弱网下积压。

## 自动化测试

- 覆盖 47 个单元测试和 42 个集成测试，包含财务、拼单、订单取消、自动签收、报损时限、权限、图片和 Excel。
- 安全测试验证旧顾客 H5 已删除、无 Token 的用户 API 返回 401。
- 前端提交前执行 JS 语法检查，Android 执行 uni-app 编译。
